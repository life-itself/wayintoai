# Memory is on disk, not in the session

**Where this came from.** Talking with Asdra about how we do memory. She tends to keep running in one Claude session: if she has a topic week after week, she keeps working in the same session. It can work, but I found myself explaining: no, you often want to start new sessions, and you want to build your set-up so that you *can* start new sessions.

**The insight.** Your memory is not the context of a session. Memory should be on disk. This is a big one.

- **Cache from the session to disk as you go.** Write what the session learns, decides and does into files (tasks, plans, reference notes).
- **It's more efficient even within the session.** A long session gets slow, costly and muddled; what's on disk can be reread cleanly.
- **More importantly, it works across sessions.** A fresh session reads the files and picks up where the last one left off. Knowledge and context build up over time instead of living in one ever-longer conversation.
- **Build the infrastructure for fresh sessions.** The goal is a working set-up (a harness) for ongoing work: the folder, the files and the routines that let any new session, yours or a colleague's, start well.

**Possible principle for the list:** "Start fresh sessions. Memory lives on disk, not in the chat."
